# ISO Standards for Software Development

## ภาพรวม (Overview)

หมวดนี้ช่วยทีมพัฒนา, QA, DevOps และผู้ดูแลสถาปัตยกรรม แปลงมาตรฐาน ISO เป็น Requirement, Control, Test และ Evidence ที่ตรวจสอบย้อนกลับได้ โดยใช้ได้กับหลาย Technology Stack

เอกสารเป็น **แนวทางเริ่มต้น** ไม่ใช่ข้อความมาตรฐานฉบับเต็ม ไม่ใช่ผล Audit และไม่ใช่หลักฐานว่าองค์กรผ่าน Certification หรือ Compliance แล้ว Project ต้องยืนยัน Standard, Edition, Scope, Owner และข้อกำหนดจริงกับผู้รับผิดชอบก่อนใช้เป็นนโยบายบังคับ

## เลือกอ่านตามงาน

| Standard | ใช้ตอบคำถามหลัก | สถานะของเอกสาร |
| --- | --- | --- |
| [ISO/IEC 27001](/standards-compliance/iso-standards/iso-iec-27001) | จะบริหาร Information Security Risk และ ISMS อย่างไร | Requirements; รองรับ Certification ใน Scope ที่กำหนด |
| [ISO/IEC 27002](/standards-compliance/iso-standards/iso-iec-27002) | จะเลือกและนำ Information Security Controls ไปใช้อย่างไร | Guidance; ไม่ใช้ Certification โดยลำพัง |
| [ISO/IEC 27034](/standards-compliance/iso-standards/iso-iec-27034) | จะฝัง Application Security ใน Lifecycle อย่างไร | Guidance หลาย Part; ไม่ใช่ Product certificate |
| [ISO/IEC 25010](/standards-compliance/iso-standards/iso-iec-25010) | Product quality ควรกำหนดและประเมินด้านใดบ้าง | Product quality model |
| [ISO 9001](/standards-compliance/iso-standards/iso-9001) | จะบริหาร Quality Management System อย่างไร | Requirements; รองรับ Certification |
| [ISO/IEC 27701](/standards-compliance/iso-standards/iso-iec-27701) | จะบริหาร Privacy Information และ PII อย่างไร | Requirements และ Guidance สำหรับ PIMS |

## เส้นทางใช้งาน

1. ยืนยัน Standard, Edition, Contract, Law และ Scope ที่เกี่ยวข้อง
2. ระบุ System, Data flow, Supplier, Environment และผู้รับผิดชอบ
3. แปลง Requirement และ Risk เป็น Control กับ Acceptance criteria
4. ใช้ [Implementation Guidelines](/standards-compliance/iso-standards/implementation-guidelines) เชื่อมกับ Workflow และ Technology Guide
5. ใช้ [Compliance Checklist](/standards-compliance/iso-standards/compliance-checklist) บันทึก Verification, Evidence และ Gap ตามจริง
6. Review เมื่อ Standard, Law, Contract, Architecture หรือ Threat เปลี่ยน

## Compliance กับ Certification ต่างกันอย่างไร?

- **Compliance/Conformity** คือการแสดงว่าขอบเขตที่ระบุตรงกับ Requirement หรือ Criteria ที่เลือก โดยต้องมี Evidence
- **Certification** คือการรับรองโดย Certification body ภายใต้ Scheme และ Scope ที่กำหนด ไม่เกิดขึ้นเพียงเพราะทีมทำ Checklist ครบ
- ISO/IEC 27002, ISO/IEC 27034 และ ISO/IEC 25010 ใช้เป็น Guidance หรือ Model ไม่ควรอ้างว่า Product หรือองค์กร “Certified” ต่อมาตรฐานเหล่านี้โดยลำพัง

## ขอบเขตของ Hub

- **Engineering Standards:** กฎกลางที่ทีมต้องปฏิบัติ
- **Technology Guides:** วิธีใช้ Framework, Database และ Tool
- **Standards & Compliance:** Source, Scope, Requirement mapping, Control intent และ Evidence expectation
- **Projects:** Implementation, Owner, Exception, Evidence reference และสถานะจริงของแต่ละระบบ

## ข้อควรระวัง

- ไม่คัดลอก Clause หรือ Control text ที่มีลิขสิทธิ์ลง Hub
- ไม่สร้าง Clause ID, Control ID หรือ Audit result จากความจำ
- Automated scan ผ่าน ไม่เท่ากับ Control มีประสิทธิผล
- เก็บเฉพาะ Reference ไปยัง Evidence ที่จำกัดสิทธิ์ ไม่เก็บ Secret, Personal data หรือ Vulnerability detail ใน Hub
- ข้อกฎหมายและ PDPA ต้องให้ Legal, DPO หรือผู้รับผิดชอบยืนยัน Applicability
