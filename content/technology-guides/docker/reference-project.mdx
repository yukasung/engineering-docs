# ตัวอย่าง Task App — ไฟล์ที่ใช้ร่วมกันทุกบท

## เรื่องนี้คืออะไร?

หน้านี้รวม Source หรือโค้ดต้นทางขั้นต่ำของ Task App เพื่อให้ Dockerfile กับ Compose มีไฟล์ที่ตรงกัน โค้ดเป็น **ตัวอย่างสำหรับ Lab ในเครื่องเท่านั้น** มี API อ่าน/เพิ่ม Task โดยไม่มี Login หรือการแยกข้อมูลผู้ใช้ ห้ามเปิดให้ผู้ใช้จริงหรืออินเทอร์เน็ต

## ใช้ทำอะไร?

ใช้เมื่อต้องการทำตามตัวอย่างทั้งชุด หากมีแอปอยู่แล้ว ให้อ่านเป็นแนวทางและปรับ Paths/คำสั่ง ไม่คัดลอกทับแอปของทีม

## ขั้นตอนการทำงาน

สร้างโฟลเดอร์ `task-demo` แยกจาก Engineering Hub แล้วคัดลอกไฟล์ตามชื่อทุกไฟล์ โฟลเดอร์นี้ยังรันด้วย Docker ไม่ได้จนเพิ่ม [Dockerfile](/technology-guides/docker/dockerfile) และ [Compose](/technology-guides/docker/docker-compose) ครบ

```python filename="backend/tasks/views.py"
from django.db import connection
from django.http import JsonResponse
from rest_framework import generics, serializers

from .models import Task


class TaskSerializer(serializers.ModelSerializer):
    class Meta:
        model = Task
        fields = ["id", "title"]
        read_only_fields = ["id"]


class TaskListCreateView(generics.ListCreateAPIView):
    queryset = Task.objects.order_by("id")
    serializer_class = TaskSerializer


def health(request):
    with connection.cursor() as cursor:
        cursor.execute("SELECT 1")
    return JsonResponse({"status": "ok"})
```

Health endpoint ตรวจ API กับการเชื่อม DB เบื้องต้น ยังไม่ได้ยืนยันว่า Migration ครบหรือสร้าง Task ได้ ต้องทดสอบเส้นทาง Task แยกด้วย

```tsx filename="frontend/src/App.tsx"
import { useEffect, useState } from 'react'
import type { FormEvent } from 'react'

type Task = { id: number; title: string }

export default function App() {
  const [tasks, setTasks] = useState<Task[]>([])
  const [title, setTitle] = useState('')
  const [error, setError] = useState('')
  const [saving, setSaving] = useState(false)

  useEffect(() => {
    fetch('/api/tasks/')
      .then(response => {
        if (!response.ok) throw new Error('อ่านรายการงานไม่สำเร็จ')
        return response.json() as Promise<Task[]>
      })
      .then(setTasks)
      .catch(() => setError('อ่านรายการไม่ได้ ตรวจ Backend และ Migration'))
  }, [])

  async function submit(event: FormEvent<HTMLFormElement>) {
    event.preventDefault()
    if (!title.trim() || saving) return
    setSaving(true)
    setError('')
    try {
      const response = await fetch('/api/tasks/', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ title: title.trim() })
      })
      if (!response.ok) throw new Error('เพิ่มงานไม่สำเร็จ')
      const task = await response.json() as Task
      setTasks(previous => [...previous, task])
      setTitle('')
    } catch {
      setError('เพิ่มงานไม่ได้ ตรวจการเชื่อมต่อแล้วลองใหม่')
    } finally {
      setSaving(false)
    }
  }

  return (
    <main>
      <h1>Task Demo</h1>
      <form onSubmit={submit}>
        <label htmlFor="title">ชื่องาน</label>
        <input id="title" value={title} maxLength={200} required
          onChange={event => setTitle(event.target.value)} />
        <button disabled={saving} type="submit">เพิ่มงาน</button>
      </form>
      {error && <p role="alert">{error}</p>}
      <ul>{tasks.map(task => <li key={task.id}>{task.title}</li>)}</ul>
    </main>
  )
}
```

Frontend เรียก URL แบบ Relative คือ `/api/tasks/` บน Origin เดียวกับเว็บ ไม่เรียก `http://backend:8000` จาก Browser และไม่ฝัง API URL แยก DEV/UAT ลง Build การส่งต่อจริงอยู่ใน `nginx.conf` บท Dockerfile

### 3. ป้องกันค่าลับและสร้าง Lockfile

```text filename=".gitignore"
.env
.env.*
!.env.example
!.env.deploy.example
node_modules/
frontend/node_modules/
frontend/dist/
__pycache__/
*.pyc
backups/
```

เมื่อสร้าง `frontend/package.json` แล้ว รันจาก `task-demo` บน Bash/Zsh เพื่อให้ Node ใน Container สร้าง Lockfile โดยไม่ต้องติดตั้ง Node ในเครื่อง:

```bash
docker run --rm --user "$(id -u):$(id -g)" -e HOME=/tmp \
  --mount "type=bind,src=$PWD/frontend,dst=/app" -w /app \
  node:22-alpine npm install --package-lock-only --ignore-scripts
```

คำสั่งนี้เขียน `frontend/package-lock.json` ลงโฟลเดอร์ที่ Mount เท่านั้น ต้องมีอินเทอร์เน็ต ตรวจและ Commit Lockfile คู่กับ `package.json` หลังจากนั้น Dockerfile ใช้ `npm ci` ติดตั้งตาม Lock นี้

## ตัวอย่างการใช้งานจริง

เมื่อเพิ่ม Dockerfile/Compose ครบและรัน Migration แล้ว เปิดหน้าเว็บ เพิ่ม “ทดลองสร้าง Task” จาก Browser และ Refresh รายการควรยังอยู่ ขั้นตอนตรวจพร้อมคำสั่งอยู่ใน [Compose Lab](/technology-guides/docker/docker-compose)

## ข้อควรระวัง

นี่เป็นแอปสาธิตขนาดเล็ก ไม่มี Authentication, Authorization, Rate limit หรือชุด Automated tests สำหรับ Business rules และไม่อ้างว่าการ Build ผ่านแปลว่าพร้อม Production

## สรุปสิ่งที่ต้องจำ

- คัดลอกไฟล์ให้ครบ รวมไฟล์ว่างและ Migration
- ต้องมี Lockfile ก่อน Build Frontend
- Frontend ใช้ `/api/` ส่วน Backend ใช้ `db:5432`
- ตัวอย่างไม่มี Login และจำกัดไว้ที่เครื่องทดลอง
