# CI/CD & Release Management

## ภาพรวม (Overview)

Continuous Integration (CI) ตรวจ Change ที่รวมกันอย่างสม่ำเสมอ ส่วน Continuous Delivery หรือ Deployment (CD) เตรียมหรือดำเนินการ Release อย่างควบคุม Release Management เชื่อม Version, Approval, Evidence, Communication และ Recovery plan เข้าด้วยกัน

## จุดประสงค์ (Purpose)

ทำให้ Build และ Release ทำซ้ำ ตรวจสอบย้อนหลัง และกู้คืนได้ พร้อมลดความแตกต่างจากการทำงานด้วยมือระหว่าง Environment

## ขอบเขต (Scope)

ครอบคลุม Pipeline control, Build artifact, Environment promotion, Approval, Configuration, Secret, ลำดับการเปลี่ยน Database, Release record, Rollback และ Forward fix โดยไม่ได้บังคับให้ใช้ CI/CD Platform เดียวกัน

## มาตรฐานสำคัญ (Key Standards)

- Build ครั้งเดียวและ Promote Immutable artifact ชุดเดิมผ่าน Environment ที่เกี่ยวข้อง
- แยก Configuration และ Secret ออกจาก Artifact พร้อมให้สิทธิ์ Deploy identity เท่าที่จำเป็น
- รัน Test, Security check และ Policy gate ที่กำหนดก่อน Promote และเก็บผลจริงไว้
- แยกสิทธิ์อนุมัติ Deploy ออกจากผู้เขียน Code เมื่อ Risk ของ Project ต้องการ
- บันทึก Source commit, Artifact identity, Configuration version, Approval และ Target environment
- กำหนด Health check, Rollout monitoring, เกณฑ์ Rollback/Forward fix และ Graceful shutdown
- แยก Database rollback ออกจาก Application rollback และตรวจ Migration compatibility ก่อน Release
