# Templates & Practical Resources

## ภาพรวม (Overview)

Templates ลดข้อมูลที่ตกหล่นและทำให้ Evidence รูปแบบสม่ำเสมอ ให้คัดลอกเฉพาะ Template ที่ Project ต้องใช้ ปรับ Owner, Workflow, Fields และสิทธิ์ให้ตรงระบบจริง ห้ามใส่ Secret, Personal data หรือรายละเอียดช่องโหว่ที่จำกัดสิทธิ์ในพื้นที่ที่คนไม่เกี่ยวข้องเข้าถึงได้

```md
- Commands/checks actually run:
- Results:
- Acceptance criteria covered:
- Not run / blocked / remaining risks:

# Review focus
- Files or decisions needing extra attention:
- Screenshots/evidence links (safe references only):
```

## 2. Code Review Checklist

```md
- [ ] Change matches approved requirements and architecture
- [ ] Correctness, edge cases, errors, retries, and concurrency reviewed
- [ ] Authentication, authorization, validation, output, and sensitive data reviewed
- [ ] API/database compatibility and migration/rollout reviewed
- [ ] Performance, query count, timeouts, and resource bounds reviewed
- [ ] Unit/integration/regression/security tests are appropriate
- [ ] Checks were run on the commit that will merge
- [ ] Documentation/runbook/ADR updated when behavior changed
- [ ] Findings are resolved, accepted with approval, or tracked with an owner
```

ใช้ [Code Review Checklist ฉบับเต็ม](/engineering-standards/code-review-coding-standards/code-review-checklist) เมื่อต้องตรวจ Change ความเสี่ยงสูง

## 7. Coding Standards Checklist

```md
- [ ] Naming communicates domain intent
- [ ] Formatter/linter configuration is followed
- [ ] Responsibilities and boundaries match project architecture
- [ ] Errors are handled without hiding causes or exposing sensitive data
- [ ] Logs/configuration contain no secrets or unnecessary personal data
- [ ] Dependencies are reviewed and lockfiles are updated
- [ ] API/database changes have compatibility and migration plans
- [ ] Tests and documentation changed with behavior
- [ ] Exceptions are documented with owner, approval, and review date
```

## 8. AI Code Review Prompt

```text
Perform a review-only analysis. Do not modify files, approve, merge, or bypass checks.
Read repository instructions, approved requirements, architecture, and validation
criteria. Review the actual diff and affected code paths.

Report only evidence-based findings. For each finding include severity/priority,
file and line, concrete scenario, impact, evidence, remediation direction, and a
verification method. Separate confirmed findings from questions. Check correctness,
security, performance, architecture, compatibility, tests, and documentation.
State the checks you ran and anything you could not verify. Never expose secrets.
```

ดู Prompt แบบ SDD/Re-review เพิ่มที่ [AI-Assisted Code Review](/engineering-standards/code-review-coding-standards/ai-assisted-code-review)
